# Haskell Development Skill

This plugin provides HLS (Haskell Language Server) integration and guidance for working with Haskell projects.

For any question about Haskell best practices, idiomatic patterns, library selection, or advanced language features, **always consult**:

- **HLS** — Haskell Language Server (`ghcup install hls`)

## Build tool

This project uses **Stack** with **hpack**. The file layout is:

```
my-project/
  package.yaml          # hpack source — edit this, not the generated .cabal
  stack.yaml            # resolver + extra-deps
  src/
    Main.hs
  test/
    Spec.hs
```

`package.yaml` is the source of truth. The `.cabal` file is auto-generated by hpack on every `stack build` — **never edit it manually**. Add language extensions, GHC options, and dependencies to `package.yaml`.

## New project setup

When scaffolding a new Haskell project, always ask the user:

> **Use RIO as the custom prelude?**
> RIO (`rio` package) replaces the standard `Prelude` with a batteries-included alternative that provides `Text`, common data structures, and opinionated defaults. Answer yes/no before generating any files.

Before writing any `package.yaml`, verify the current `rio` version on Hackage (<https://hackage.haskell.org/package/rio>) and Stackage (<https://www.stackage.org/package/rio>), then use the latest available version.

### Without RIO (standard Prelude)

```yaml
name: my-project
version: 0.1.0.0

dependencies:
  - base >= 4.18

executables:
  my-project:
    main: Main.hs
    source-dirs: src
    ghc-options:
      - -Wall
    default-extensions:
      - GHC2021
```

### With RIO

Add `rio` to dependencies and enable `NoImplicitPrelude` globally so GHC never pulls in the standard Prelude:

```yaml
name: my-project
version: 0.1.0.0

dependencies:
  - base >= 4.18
  - rio >= 0.1.24.0   # verify latest at https://hackage.haskell.org/package/rio

executables:
  my-project:
    main: Main.hs
    source-dirs: src
    ghc-options:
      - -Wall
    default-extensions:
      - GHC2021
      - NoImplicitPrelude
```

In every module, replace `import Prelude` with:

```haskell
import RIO
```

RIO re-exports `Text`, `ByteString`, `Map`, `Set`, common lens combinators, and more. See the [RIO README](https://github.com/commercialhaskell/rio#readme) for the full export list.

## Language extensions

Enable per-file with a pragma at the top:

```haskell
{-# LANGUAGE OverloadedStrings #-}
{-# LANGUAGE RecordWildCards   #-}
```

Or project-wide in `package.yaml`:

```yaml
default-extensions:
  - OverloadedStrings
  - RecordWildCards
```

Common extensions:

| Extension | Purpose |
|-----------|---------|
| `OverloadedStrings` | String literals for `Text`/`ByteString` |
| `RecordWildCards` | `let Foo{..} = x` pattern syntax |
| `DeriveGeneric` | Auto-derive `Generic` for serialization |
| `ScopedTypeVariables` | Bring type variables into scope in let/where |
| `TypeApplications` | `f @Int x` explicit type application |
| `LambdaCase` | `\case x -> ...` shorthand |
| `TupleSections` | `(, y)` partial tuple application |
| `GHC2021` | Sensible bundle of stable extensions (recommended) |

## Lenses

Lenses are available via RIO's bundled re-exports or a standalone package such as `microlens` / `microlens-platform`.

### Naming rule — always prefer named functions over operators

Use the named combinator forms. **Never use operator syntax** (`^.`, `.~`, `%~`, etc.) unless the user explicitly requests it.

| Operation | Preferred | Avoid |
|-----------|-----------|-------|
| Read a field | `view fieldL record` | `record ^. fieldL` |
| Set a field | `set fieldL value record` | `record & fieldL .~ value` |
| Modify a field | `over fieldL f record` | `record & fieldL %~ f` |

Named functions are more readable for newcomers, easier to compose with `$` and `.`, and grep-friendly.

### Defining lenses with Template Haskell

Name record fields as `_type_field` (underscore, type name, underscore, field name — all snake\_case). `makeLenses` strips the leading underscore to derive the lens name:

```haskell
{-# LANGUAGE TemplateHaskell #-}

data Config = Config
  { _config_host :: Text
  , _config_port :: Int
  }

makeLenses ''Config
-- generates: config_host :: Lens' Config Text
--            config_port :: Lens' Config Int
```

## hie.yaml — explicit HLS cradle configuration

HLS auto-detects Stack via a discovery process called the "cradle". For most single-package projects this works without any configuration. Add a `hie.yaml` at the project root when:

- HLS reports "could not find a cradle" or fails to load modules
- The project has an unusual source layout not covered by `package.yaml`
- You need per-component overrides (e.g. different flags for library vs. test suite)

### Stack cradle

```yaml
cradle:
  stack:
```

With explicit component mapping:

```yaml
cradle:
  stack:
    - path: "src"
      component: "my-project:lib"
    - path: "test"
      component: "my-project:test:my-project-test"
    - path: "app"
      component: "my-project:exe:my-project"
```

### Direct GHC cradle (no build tool)

For standalone scripts or generated projects without Stack:

```yaml
cradle:
  direct:
    arguments:
      - "-isrc"
      - "-XOverloadedStrings"
```

### Checking the active cradle

```bash
haskell-language-server-wrapper --print-cradle path/to/File.hs
```

This prints which cradle HLS resolved for that file — useful for diagnosing load failures.

## HLS features (automatic — no action needed)

When the plugin is installed, `haskell-language-server-wrapper --lsp` starts automatically and provides:

- Type information on hover
- Go-to-definition and find-references
- Inline diagnostics (type errors, warnings, HLint suggestions)
- Code actions: add imports, apply HLint fixes, fill typed holes (`_`)
- Rename symbol
- Format on save via Fourmolu or Ormolu
- Completions for identifiers, imports, and pragmas

HLS picks up Stack automatically and uses the GHC version pinned by the project.

---

## Formatting

HLS integrates with Fourmolu (default) or Ormolu. To configure Fourmolu, add a `fourmolu.yaml` at the project root:

```yaml
indentation: 2
comma-style: leading
record-brace-space: true
```

Run manually:

```bash
fourmolu --mode inplace src/**/*.hs
```

---

## Linting

HLint runs through HLS automatically. To run it standalone:

```bash
hlint src/
```

Apply suggestions automatically:

```bash
hlint --refactor --refactor-options="--inplace" src/
```

## Common GHC flags

Add to the relevant target in `package.yaml` under `ghc-options`:

| Flag | Effect |
|------|--------|
| `-Wall` | Enable most warnings |
| `-Wextra` | Additional warnings |
| `-Werror` | Treat warnings as errors |
| `-O2` | Optimized build |
| `-prof` | Profiling support |
| `-threaded` | Enable the threaded RTS |
| `-rtsopts` | Allow `+RTS` flags at runtime |

## Troubleshooting

**`haskell-language-server-wrapper` not found**
Install via `ghcup install hls` and ensure `~/.ghcup/bin` is on `$PATH`.

**HLS fails to start / cradle error**
HLS needs a `stack.yaml` at the project root to locate the project. Run `stack build` at least once so the build plan is resolved. If auto-detection still fails, add a `hie.yaml` (see above).

**Type errors after adding a new module**
Run `stack build` once so GHC discovers the new source file; then HLS picks it up on the next reload.

**Stack project: changes to `.cabal` are lost**
The `.cabal` file is regenerated by hpack on every `stack build`. Always edit `package.yaml` instead.

**Multiple GHC versions**
Use `ghcup` to switch: `ghcup set ghc 9.6.4`. HLS uses the project-pinned GHC via the wrapper script.
